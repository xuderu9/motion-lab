# 事件流架构（方案 B）—— 从「排版一次」到「一条时间轴」

> 依据：`studio/MOTION-FINDINGS.md`。核心数字：**我们 87% 的像素 3 秒没动过，参考片 0.2%**。
> 而且去掉颗粒噪声后这个结论不变（shipin3 从 0.2% → 0.3%，我们从 86.9% → 83.8%），
> 所以它不是测量伪影，是真结构问题。
>
> 方案 A（在现有版式里加轮换）已经被实验否定：panel v0 加卡片轮换后 hold3 只从
> 99.3% 降到 67.4% —— 因为卡片只占 30% 面积，纸底/标题/黑条那 70% 一动不动。

---

## 1. 为什么"版式"这个抽象注定出 PPT

现在的模型：

```
ShotSpec = { layout, variant, content }   →   paintLayout(g, t, ...)
```

`paintLayout` 的写法必然是：**t=0 时把版面排好，之后所有东西都在原位**。
只要版式函数的形状是"给定 t，画一个完整画面"，它就默认了"画面是一个静态构图"。
轮换卡片只是在这个构图上加一点扰动，动不了 70% 的底。

**版式 = 快照。快照 = PPT。**

---

## 2. 新抽象：图层 + 生命周期 + 相机

一个镜头不再是一个版式，而是一份**编排谱（Score）**：

```ts
type Layer = {
  id: string;
  /** 出生 / 死亡（秒）。死亡之后**必须**不再绘制 */
  birth: number;
  death: number;
  /** 这一层自己的绘制函数；u = 本地进度 0..1 */
  draw: (g: CanvasRenderingContext2D, u: number) => void;
  /** 纵深：0 = 背景，1 = 主角。用于视差、景深、遮挡排序 */
  depth: number;
};

type Score = {
  layers: Layer[];
  /** 相机：全程不允许速度为 0，且不允许周期性重复 */
  camera: (t: number) => { x: number; y: number; zoom: number; roll: number };
};
```

### 三条硬约束（它们直接对应指标）

| 约束 | 为什么 | 对应指标 |
|---|---|---|
| **除相机外，任何层的 `death - birth` 不超过镜头时长的 70%** | 不许有东西挂满全程 | hold3 |
| **任何时刻至少有 2 层处于 enter 或 exit 阶段** | 画面一直在重排 | active_frac |
| **相机速度全程 > 0，且路径不自交重复** | 整屏持续位移 | hold3 |

### 关键补充：大面积区域必须有**纹理**

实测发现：空间镜头 active_frac 3.63%（比参考片还高），但 hold3 仍有 33.8%。
那 33.8% 是**深色背景和暗角** —— 相机在动，但背景是纯色，**平移纯色不改变任何像素**。

> 推论：**纯色的大面积区域，无论怎么动，hold3 都降不下来。**
> 所以背景板必须带低对比度的纹理/渐变结构，让相机一动就有像素变化。

这不是"加呼吸感"。区别在于：
- 呼吸 = 同一块颜色周期性明暗/缩放 → 全局同相位，3 秒尺度上仍算"没变"，且被明令禁止
- 纹理 + 相机 = 结构在空间上移动 → 每块像素在 3 秒内都被新内容覆盖过

## 3. 镜头内的节拍（这是参考片真正在做的事）

参考片平均镜头 14.6 秒，hold3 却是 1~12%。说明它在**镜头内部不断重组**。
推测的结构（待验证）：

```
0.0s  新章开始：背景层换、大标题进场
1.8s  标题缩成角标（迁移，不是消失）
3.0s  第一组内容进场（3~4 个元素）
5.5s  第一组退场，第二组进场（重叠 0.6s）
8.0s  一个"证据"元素单独放大（其余退到背景）
11.0s 收束：元素归拢成一行结论
13.5s 结论上移变成下一段的标题（跨镜头继承）
```

**"跨镜头继承"是重点**：参考片 161 秒只有 11 次硬切，很多"段落切换"其实是
一个元素从上一段迁移到下一段。这比硬切更"连续"。

## 4. 落地步骤（每步都有可测出口）

| 步 | 内容 | 出口指标 |
|---|---|---|
| **F1** | `score.ts`：Layer/Score 运行时 + 相机轨道 + 层排序 | 能渲出一个 8 秒镜头 |
| **F2** | `ground.ts`：带纹理的背景层（确定性噪声贴图 + 相机偏移） | 纯色区域消失 |
| **F3** | 第一个 Score 版式：`flow/opening`（开场）与 `flow/evidence`（证据页） | **单镜头 hold3 ≤ 25%** |
| **F4** | 迁移：把 18 个镜头的 plan 改成 Score 序列 | 全片 hold3 ≤ 20% |
| **F5** | 追平参考：跨镜头继承 + 节拍加密 | **全片 hold3 ≤ 15%（验收线）** |

F1~F3 是骨架，F4~F5 是内容。

## 5. 与现有代码的关系（不推倒重来）

- `shot/motion.ts`、`post.ts`、`lifecycle.ts` 全部保留，是新架构的素材库
- `layouts/*` 不删除：每个版式退化成"一个画完整画面的 Layer"，
  在 Score 里可以当作一个 `depth=0.5`、`death = birth + 4s` 的层来用
  —— 也就是**旧版式变成新体系里的一个元素**，而不是整段画面的全部
- `space.ts`（3D 走廊）保留：它恰好是"相机速度不为 0"的正例，只要补上
  **背景纹理**（现在背景是纯色，所以 hold3 卡在 33.8%）
