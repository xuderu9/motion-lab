## 2. 硬阈值

| 指标 | 必须落在 | 为什么 |
|---|---|---|
| 屏外（房间）平均亮度 | 77 ~ 192 | 曝光系数 = 房间目标亮度 / 实测亮度，要落在 0.55~1.40 |
| 屏幕占全帧面积 | 9% ~ 18% | <9% 房间补不回来（暗页帧跌破 94）；>18% 暗主题屏太大 |
| 屏幕宽（1080p） | ≥ 480 px | 34px 画布字号 × (宽/1600) ≥ 10px |
| 物理屏幕比例 | 4:3 | 画布 1600×1200；比例不符时四角单应会自动把内容拉伸 |

曝光公式（`detect-screen.py` 内置）：

```
房间目标亮度 R = ((96 - 0.315) / 0.955 - 50·a) / (1 - a)     # a = 屏幕面积占比
exposure = R / 该板实测屏外亮度
```

## 4. 三个实测教训

### 4.1 提示词里的「夜晚」会毁掉亮度账
即梦收到「夜晚/夜景/虚化」会把**整个房间**压到 48~67，要补到房间目标亮度需要 1.6~2.3 倍曝光，
台灯和窗景全部爆掉。而现用的 `desk-night` 是 91.2 —— 同为夜景却亮一倍。
**可用方向：白天 / 黄昏 / 明亮室内 / 大面积窗户透光。暗调交给主题和压暗层。**

### 4.2 太小能裁大，太大裁不了
即梦无法精确控制平板在画面里的比例（16 张候选只有 4 张天然落在窗口内）。
裁掉四周等于放大屏幕，面积按裁剪倍率²增长；但特写（20%+）**修不了**，只能重新生成。
上采样倍率控制在 1.45 以内，超过就重新生成。

### 4.3 自动定位会认错亮区 —— **每张板必须先实渲一帧再提交**
`office-bright` 第一版就是这么翻车的：自动检测把**白墙**当成了屏幕，
渲出来内容悬在半空。改用 `--seed` 指定平板内一点后才发现真实屏幕只有 6.25% 面积，
再裁 1.30 倍才达标。

**规矩：`detect-screen.py` 的叠加图只能证明「找到一块像屏幕的区域」，
证明不了「找到的是屏幕」。唯一可靠的验证是渲一帧看内容贴不贴。**

## 4.4 特写机位：不是放宽判据，是限制它能配的主题

特写屏占比 **22.29%**，是其它环境的 1.5~2.4 倍。这带来一个算术后果：

```
整帧 = (1 - a)·房间 + a·屏内
a = 0.2229 时：
  亮主题（屏内 225）→ 整帧 ≈ 117
  暗主题（屏内  50）→ 整帧 ≈ 77   ← 远低于「暗页帧 ≥94」
```

抬曝光救不回来：要托住暗页帧得到 94，房间亮度得压到 114，
此时亮页帧会冲到 137，整片平均直接出界。

**所以特写的解锁条件不是改判据，而是在注册表里写 `allowedThemes`：**

```json
{ "name": "closeup", "allowedThemes": ["light", "warm-sand"], "env": { ...,"exposure": 1.236 } }
```

规划器 `pickEnvironment()` 会先按主题过滤环境，再按版式偏好挑——顺序不能反。

配套两条：

- **曝光定标方式不同。** 普通环境按「暗页帧 → 96」定标（`detect-screen.py` 默认）；
  只配亮主题的环境要按「亮页帧 → 116」定标（加 `--light-only`）。
  用错定标会得到偏暗或偏亮 20 级的曝光。
- **特写占比建议 ≤1/3。** 单帧 117.9 已经在 105±12 的上沿；超过 1/3 的镜头是特写，
  整片平均会顶出 117。规划器现在按版式偏好轮换，实测约 1/5。
