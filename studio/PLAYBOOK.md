# 交付流程规则（教训总结）

> 起因：屏幕对齐这一个环节，改了 10 轮才对。后面还有 SRT 时间轴、多镜头编排、字幕同步、
> 版式库、批量出片等环节，按这个效率不可行。本文定下后续所有环节的执行规则。

---

## 一、这次的病根

**把"渲染 + 用眼睛看"当成了验收器。** 后果：

- 每轮都要渲染（30–70 秒）+ 读图 + 判断，一轮 5 分钟起
- 判断标准是主观的，所以「差一点」这种状态无法收敛
- 每次只验证一个假设，假设错了就重来

实测浪费：对齐 10 轮里 8 轮可避免；字号 1 轮渲染可避免。

---

## 二、五条规则

### 规则 1：能算的先用公式算，不要渲了再看

任何"渲出来才知道"的量，先问一句：有没有解析式？

| 问题 | 公式 | 本次实例 |
|---|---|---|
| 文字在成片里多大 | `设计字号 × (屏幕像素宽 / 画布宽)` | 34 × (488/1600) = 10.4px |
| 屏幕占画面比例 | `四边形面积 / (1920×1080)` | 约 10% |
| 3 分钟片子渲染多久 | `单帧耗时 × 总帧数` | 66s/900帧 → 5400帧 ≈ 6.6 分钟（**已超 5 分钟红线**）|
| 素材成本 | `镜头数 × 单价` | 20 个镜头 × 1 积分 = 20 |

**数列算就能排除的方向，不要用渲染去排除。**

### 规则 2：动手前先写验收脚本，脚本 PASS 才算完

没有可执行检查的环节，不许开工。检查脚本必须输出**数字 + PASS/FAIL**，不能输出"看起来不错"。

现有脚本（`studio/tools/`）：

| 脚本 | 判据 |
|---|---|
| `quad-snap.py` | 求屏幕四边形，输出 4 角坐标 + 收敛位移 |
| `check-overflow.py` | 品红探针 → 溢出像素必须为 **0** |

### 规则 3：有目标函数的参数用搜索，不要手工调

对齐问题的本质是一个优化问题：**最大化"内容在屏幕内"的面积，约束"溢出 = 0"**。
8 个参数（4 个角 × 2 坐标），完全可以让脚本搜，而不是我猜一轮改一轮。

同类可自动搜索的参数：亮度曲线、缓动参数、构图占比。

### 规则 4：主观选择一次给多个版本

改圆角半径、换配色、选转场这类主观判断，**一次渲 3–4 个变体并排给人类挑**，
而不是「改一版 → 问一次 → 再改一版」。一轮沟通换 4 个选项，而不是 1 个。

### 规则 5：互不影响的改动合并成一批

字号、圆角、配色、动效速度互不影响时，一次改齐、一次渲染。
不要"改一处 → 渲 → 看 → 再改一处"。

## 三、后续环节的预定义验收

每个环节动手前，先认领它对应的验收指标。**指标不达标不算完成。**

| 环节 | 验收指标 | 测量方式 |
|---|---|---|
| 单镜头模板 | 溢出 0px、亮度 105±10、静止帧 <15%、最长冻结 <0.3s | check-overflow + 亮度/帧差脚本 |
| 版式库 | 每种版式 1 个样例镜头，全部通过单镜头指标 | 批量跑脚本 |
| SRT → 时间轴 | 解析出的段落边界与人工标注误差 <0.3s | 对照表 |
| 字幕同步 | 每条字幕入场时间误差 <100ms | 时间轴 vs SRT 逐条比对 |
| 多镜头编排 | 成片总时长 = SRT 总时长 ±0.5s；无黑帧 | ffprobe |
| 音频 | 音画偏移 <50ms | 波形对齐 |
| 性能 | 3 分钟片渲染 <5 分钟 | 计时 |
| 批量出片 | 换一份新 SRT，无人值守出片成功 | 端到端跑一次 |

---

## 四、每次交付给人类的格式

不再让人类"看一版说一版"，而是：

1. **结论先行**：通过 / 未通过，卡在哪一条指标
2. **数字表格**：所有指标的实际值 vs 目标值
3. **可选版本**：主观项给 2–4 个变体，一次选定
4. **不再贴中间过程图**（除非是要人类做主观判断的那一项）

## 五、已经踩过的坑（避免重复）

| 坑 | 教训 |
|---|---|
| 在缩略图上量坐标 | 会系统性偏小。必须裁出来放大 ≥2 倍 |
| 用阈值分割找屏幕边界 | 边框高光/下方阴影/深色书架会破坏假设。**用梯度吸附** |
| 用"取极值点"定四角 | 极值点只由 1 个像素决定。**必须拟合边线再求交** |
| 用白色检测溢出（照片背景） | 被窗户灯光/台灯光晕污染 25%。**用品红等照片中不存在的颜色** |
| PowerShell 改源码 | `-Encoding utf8` 在 PS5.1 下按 ANSI 读，中文全乱码。**用编辑工具** |
| 渲染输出接 PowerShell 管道 | `Select-Object` 提前终止管道 → node 抛 `write EOF` 假失败。**落盘再读** |
| `.ts` 文件里写 JSX | 报 `Unexpected ">"`。合成表要单独放 `.tsx` |
| R3F 相机用 `useEffect` 设 | Remotion 截图在 paint 之后、useEffect 之前 → 拿到默认相机 |
| `<ThreeCanvas>` 传 camera prop | 会被 R3F 重新应用、覆盖 rig 的设置 |
| 视频渲染不加 `--concurrency=1` | `EffectComposer.addPass` 抛 `alpha` 空引用 |
| 界面按 1600 宽设计却显示在 488px 屏幕上 | 文字必然糊。**先算有效字号** |
