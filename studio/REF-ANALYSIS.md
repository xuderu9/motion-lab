## 2. 最关键的结构发现：整片被框在一个「浏览器窗口」里

我一开始只看到「白底卡片」，实际上**每张卡都是浏览器里的一个页面**：

- 顶部有一条 **5% 高的标签栏**（实测 y=0..54px），标签是**章节导航**：
  `Claude 剪的片 ｜ 岗位一：调研脚本 ｜ 岗位二：剪辑 ｜ 岗位三：做计划 ｜ 岗位四：动态图形 ｜ 岗位五：检查成片 ｜ 岗位六：按意见改 ｜ 这条片花了多少`
- 当前章节的标签**高亮**（浅蓝底），随视频推进切换
- 底部有一条细状态栏（约 1.5%）

这条设计解决了一个我们没解决的问题：**观众永远知道现在讲到第几章**。
它同时替代了「转场」——换章节只换高亮，画面不黑。

## 3. 卡片展现方式（分类，带时间码）

### A. 整帧单卡（最主力，v1 大部分镜头）
结构：纯色底（无渐变）+ 左对齐大标题 + 若干「小标签 + 视觉块」的行 + 底部字幕。
例：`v1 @178s` 白底卡「a few *frames*」：标签 `PICTURE · CAMERA` → 8 张缩略图横排 → 标签 `SOUND · MICROPHONE` → 波形 → 括号标注 `5 FRAMES · 167 MS`。

### B. 大字冲击卡
结构：纯色底 + 一个巨大数字/词，逐词出现，修饰词用**衬线斜体 + 强调色**。
例：`v1 @468s` 红底卡：`5`（粗无衬线）→ `5 months`（months 为斜体衬线），字号 **20.7% 画面高**。
另见 `v1 @400s` `8,000+`、`@494s` `4.4 billion`、`v3 @190s` `30万`。

### C. 卡片横排（缩略图条 / 卡片列）
结构：一排等宽卡片横向排列，其中一张高亮（描边/放大），可逐张推进。
例：`v1 @178s` 的 8 张缩略图；`@465s` 的六张「岗位」卡；`@529s` 的一排缩略图。

### D. 卡墙 / 马赛克
结构：大量小卡片密铺整屏，常带轻微透视倾斜与视差，整体缓慢漂移。
例：`v1 @176s`（4×3 倾斜拼贴）、`@300s`（10 帧网格）、`@522s`（6 格截图墙）。

### E. UI 面板卡（v2 主力）
结构：一整屏「应用界面」——侧边栏 + 表格 + 行 + 内嵌小卡；像真截图。
例：`v2 @205s`：「Render, look, fix」面板从左侧滑入，右侧再浮现第二块（`ABOUT / RENDER STYLES / CONTACT SHEET / MESSAGE RESULTS` 内嵌小卡）。
其余：`@103s` 表格、`@163s` 胶囊列表、`@240s` 侧栏+内容、`@269s` 数据卡。

### F. 悬浮卡（v3 主力）
结构：真人在背景，1~3 块 UI 卡片以 5~10° 倾斜浮在前面，带投影。
例：`v3 @63s`、`@77s`、`@163s`。

### G. 逐词浮现的标题
结构：标题不是一个整体出现，而是**一个词一个词**落到位置上。
例：`v1 @178s`：先 `a`，再 `a few`，再 `a few frames`；`@244s` `text moves`。

### H. 扫描 / 游标 / 括号标注
结构：一条竖线扫过内容（播放头），把一段范围框起来并标数值。
例：`v1 @178s`：红色播放头 + 括号 + `5 FRAMES · 167 MS`。

## 4. 量出来的排版数值（1920×1080）

白底卡 `card-afew.png`（背景 RGB **248,248,248**，占 75%）：

| 小标签 | 269..288 | 20px | 1.9% | 全大写、字距很宽、灰 |
| 缩略图条 | 300..459 | 160px | 14.8% | x=150..1759（宽 1610px） |
| 标签 | 507..526 | 20px | 1.9% | |
| 波形 | 567..692 | 126px | 11.7% | |
| 标注 | 768..787 | 20px | 1.9% | |
| 字幕（中） | ~790..870 | ~80px | 7.4% | 居中，白色带投影 |

红底卡 `card-5months.png`（背景 RGB **216,40,8**，占 70%）：

| 元素 | 高度 | 占画面高 |
|---|---|---|
| 顶部标签栏 | 55px | 5.1% |
| 巨字 `5 months` | 224px | **20.7%** |

**要点**
1. **背景是纯色，不是渐变**（248 或 216,40,8），我们现在的主题底色是渐变，方向反了。
2. **左右边距约 8%**（150/1920），上下内容区从 8% 到 72%，底部 28% 留给字幕。
3. **主标题 10.6%~20.7% 画面高**，比我们现在的 40px 级大一个数量级。
4. **小标签 20px、全大写、宽字距**——用字号对比拉层次，不靠颜色。
5. 中英双语字幕常驻：中文大字 + 英文小字，**关键词用黄色**。

## 5. 字体与色彩

- 主标题：**几何无衬线粗体**（`a few` / `5`）+ **衬线斜体强调**（`frames` / `months`，红色）
  这是全片最强的视觉签名：**同一句话里混排两种字体**。
- 标签：等宽或大写无衬线，字距 +0.2em 左右。
- 强调色：红橙 `≈#D92808`、品红 `≈#C2185B`、黄（字幕关键词）。
- 底色：近白 `#F8F8F8`、纯黑 `#0A0A0A`、红橙。

## 6. 动效（连拍观察）

| 手法 | 观察 |
|---|---|
| 卡片进场 | 从画面外滑入（v2 @205s 从左滑入），或直接硬切（v1 多数） |
| 文字 | 逐词出现，位置已定，只做透明度 + 位移 |
| 缩略图条 | 每张卡片独立轻微缩放/高亮推进 |
| 播放头 | 竖线匀速扫过，扫到哪里哪里高亮 |
| 数字 | 计数上升 / 砸入 |
| 背景 | **基本不动**（纯色，没有渐变流动） |

## 7. 与当前系统的差距（要补的）

| 差距 | 现状 | 需要 |
|---|---|---|
| **顶部章节导航** | 无 | 新增 chrome 层：标签栏 + 当前章节高亮，跨镜头常驻 |
| **纯色卡片底** | 主题是渐变 | 新增 `cardStyle`：纯色底（白/黑/强调色）+ 前景色 |
| **超大主标题** | 40px 级 | 标题按「画面高的 10~20%」取字号 |
| **无衬线 + 衬线斜体混排** | 单一字体 | 字体配对 token：`displaySans` / `displaySerifItalic` |
| **行带式布局**（标签→视觉→标签→视觉） | 无 | 新增 band 布局器 |
| **字幕层** | 未做（M5-g） | 中英双语 + 关键词高亮 |
| **卡片横排/卡墙** | 场景里只有 flyRow | 按 §3 的 C/D 两类补齐 |
| **逐词浮现** | 无 | 文字动画原语 |

## 8. 对架构的修正

原来的四轴（content / layout / scene / presentation）不变，但要补两个**常驻层**：

```
chrome 层   顶部章节导航 + 底部状态栏（跨镜头，不属于任何单镜头）
content 层  卡片内容（现有 layout / scene）
subtitle 层 中英双语字幕（跨镜头，由 SRT 驱动）
```

chrome 和 subtitle 都挂在 `Film` 上而不是 `Shot` 上——它们跨镜头存在，
换镜头时只有内容变，chrome 只换高亮。这也顺带解决了「转场」：
章节切换不需要黑场，换高亮即可。
